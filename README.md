# Строительство газопровода — хакатон НГУ

## Базовая стратегия Best Fit

Сравнение двух алгоритмов по KPI каждого из 15 публичных тестов: [KPI_COMPARISON.md](KPI_COMPARISON.md), [таблица CSV](reports/kpi_comparison.csv). В повторном прогоне Best Fit лучше на тестах 11, 13 и 15, статистическая версия — на тесте 8; на остальных 11 тестах KPI одинаковый.

По отдельному запросу реализован **`solution_best_fit.cpp`** — самостоятельный файл для отправки с компилятором **GCC C++ 14.2 (64-bit, C++20, msys2)**. Он использует только Best Fit на всей последовательности команд.

Свободные промежутки находятся одновременно в `std::map<начало, длина>` и `std::set<pair<длина, начало>>`. Поиск через `lower_bound` выбирает самый короткий подходящий промежуток, а при равной длине — самый левый. Труба занимает левый край, остаток возвращается в оба индекса. Если места нет, используется свободный хвост и докапывается `(недостающая_длина + 19) / 20` участков. При удалении освобождённый участок объединяется с обоими свободными соседями. PID соответствует порядку поступления труб и не переиспользуется.

Сложность команды — `O(log(G + 1))` с амортизированным добавлением записи трубы, память — `O(P + G)`, где `G` — число свободных промежутков, `P` — число поступивших труб. После каждого ответа выполняется `std::flush`; команда `0` не получает ответа. Ввод читает доступные байты через `ReadFile` в Windows и `read` в Linux, не ожидая заполнения буфера.

Сборка и проверки в PowerShell из корня проекта:

```powershell
$env:PATH = (Join-Path $PWD '.tools/w64devkit/bin') + ';' + $env:PATH
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -static solution_best_fit.cpp -o build/solution-best-fit.exe
python tools/check_best_fit.py build/solution-best-fit.exe
python tools/check_open_tests.py --solution build/solution-best-fit.exe --source solution_best_fit.cpp --report reports/open_tests_best_fit_windows.json
```

Для Linux: `g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic solution_best_fit.cpp -o build/solution-best-fit`.

Проверка по независимой метровой модели прошла 25 сценариев (20 032 команды); отдельно пройден сценарий из 200 000 труб длиной 40 м. Проверены немедленные ответы, фрагментированный ввод, CRLF, EOF и остановка по `0`.

Официальный интерактор подтвердил корректность всех 15 открытых тестов, сумма баллов — **28,3758375994 из 32,1**. Отчёт: `reports/open_tests_best_fit_windows.json`. В финальном локальном прогоне тест 15 потребовал **5,34375 с CPU** при лимите 5 с, пиковая память — около 5,5 МиБ; остальные 14 тестов уложились в ограничения. Скрипт проверки возвращает код 1 из-за превышения времени, хотя все ответы корректны. Прохождение лимита времени на сервере не подтверждено.

## Алгоритм

Первые 200 поступлений используют Best Fit. На следующих 200 поступлениях постепенно включается оценка свободных промежутков по статистике последних 1024 поступлений. Удаление трубы не уменьшает число поступлений и не удаляет её длину из статистики.

Для `k` предыдущих поступлений в окне частота длины `l` сглаживается равномерным априорным распределением общей массой 1:

```text
p[l] = (count[l] + 1/40) / (k + 1)
q[l] = 0.75 * p[l] + 0.25 * l * p[l] / sum(j * p[j])
Phi(g) = g * sum(q[l] для l > g), 1 <= g < 40
Phi(0) = Phi(g >= 40) = 0
a = clamp((номер текущего поступления - 200) / 200, 0, 1)
score(h, x) = (1-a) * (h-x) + a * (Phi(h-x) - Phi(h))
```

Здесь `h` — длина свободного промежутка, `x` — длина текущей трубы. Выбирается минимальный `score`. При равенстве с точностью `1e-9` выбирается меньший промежуток, затем меньшая начальная позиция. Укладка выполняется с левого края. Текущая труба попадает в статистику после выбора места.

В C++ свободные интервалы хранятся в двух согласованных индексах: `std::map` по началу и `std::map<длина, std::set<начало>>` по длине. После удаления соседние интервалы объединяются. Если подходящего промежутка нет, используется свободный хвост и докапывается минимально необходимое количество участков по 20 м. Траншея не сокращается.

За один поиск оценивается не более 41 кандидата: по одному для каждой подходящей длины до `x+39` и один минимальный промежуток длиной от `x+40`. Сложность команды — `O(log G + 40)`, где `G` — число свободных интервалов. Формулы, параметры и порядок выбора кандидатов сохранены при переносе с Cangjie.

Параметры являются начальными гипотезами. Превосходство над Best Fit без отдельного сравнения не заявляется.

## Сборка C++

Для Linux/WSL:

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic solution.cpp -o solution
bash ./build_cpp.sh --test
```

Для Windows с GCC/MinGW:

```powershell
.\build_cpp.ps1 -Test
# Компилятор в другом каталоге:
.\build_cpp.ps1 -CompilerPath 'C:\msys64\ucrt64\bin\g++.exe' -Test
```

Скрипт Windows использует `g++.exe` из `.tools/w64devkit/bin/` либо из PATH. Локально доступен переносимый [GCC 14.2 из w64devkit 2.0.0](https://github.com/skeeto/w64devkit/releases/tag/v2.0.0). Компилятор и бинарные файлы исключены из Git. Windows-сборка статическая; дополнительный Cangjie SDK для C++ не нужен. Исходник также использует только возможности C++17.

Результат: `build/solution-cpp.exe` в Windows, `build/solution-cpp` в Linux. Журналы модульных тестов сохраняются в `build/unit-tests-cpp-windows.log` и `build/unit-tests-cpp-linux.log`.

Программа получает команды интерактора без заголовка тестового файла. Ввод читает доступные байты и не дожидается заполнения буфера. Каждый ответ полностью отправляется сразу, до чтения следующей команды; `0` завершает программу без ответа. Вывод идёт напрямую через системные функции, без накопления ответов в stdio. Диагностика выводится только в `stderr`.
