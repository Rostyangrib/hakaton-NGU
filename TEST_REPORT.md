# Результаты проверки C++-решения

Дата: 17 октября 2026 года. Исходник: `solution.cpp`, коммит `85b9a620fdf4ec8d70f60d0666964093719dac61`.

**Все 15 открытых тестов приняты официальным интерактором в Windows и Linux/WSL.** На всех 280156 командах числовые ответы совпали с Cangjie-версией `79de461`. Сумма баллов: **28.348606685**. Штатный `runner.py` подтвердил **28.348606686**; небольшое отличие последних цифр вызвано округлением `score.txt` самим интерактором.

Сумма весов тестов — 32,1. Это не доказанный достижимый максимум: траншея не сокращается, а занятая длина после удалений может быть меньше пиковой нагрузки. Это балл локального интерактора; языковые бонусы и скрытые тесты в него не включены. Сравнение качества с отдельной Best Fit-версией этот отчёт не охватывает; превосходство эвристики над ней здесь не заявляется.

## Корректность и ограничения

- GCC 14.2.0 / MinGW-w64 / C++20, Windows x64: 15/15 корректных тестов. В финальном прогоне максимальное полное CPU-время — **3.141 с**, пиковый рабочий набор — **5.44 МиБ**. Все тесты в этом прогоне уложились в 5 с CPU и 256 МиБ.
- GCC 13.3.0 / C++20, Ubuntu 24.04.4 / WSL2: 15/15 корректных тестов. Тест 15 дал **6.448 с CPU**, что превышает 5 с; максимальный RSS — **35.14 МиБ**. Выполнение CPU-ограничения в этой среде не подтверждено.
- Те же 13 модульных проверок прошли в Windows, Linux и Linux-сборке с AddressSanitizer + UBSan. Проверены 100 коротких и 6 длинных случайных сценариев — 27 200 команд с независимой метровой моделью и сверкой выбора с полным перебором. Отдельно проверены 1000 циклов повторного использования промежутка.
- Проверен потоковый протокол: немедленные ответы до отправки следующей команды, частичные команды, пробелы, CRLF, EOF без перевода строки, отсутствие ответа на `0`, отклонение неверных команд и 10 000 команд через границы входного буфера.
- Все 20 распакованных файлов организаторов побайтово совпадают с `2.zip`. Условие, тесты, интерактор и `runner.py` не изменялись.

## Разброс времени и граница проверки

Штатный `runner.py` на тесте 15 показал **1,719 с пользовательского CPU** и около 5,4 МиБ памяти. Он периодически опрашивает процесс, учитывает только `cpu_times().user` и может пропускать короткие процессы. Его время не равно полному CPU-времени из таблицы.

Для той же финальной C++-сборки сохранены и другие замеры Windows: **5.172 с** в полном прогоне с журналами в рабочем каталоге и **3.219 с** при отдельном запуске теста 15. Эти результаты не удалены: [прогон с журналами в проекте](reports/cpp_windows_workspace_logs.json), [отдельный запуск](reports/cpp_windows_test15_repeat.json).

В финальном измерителе синхронные журналы интерактора пишутся в системную временную папку и копируются в `build/open-tests/` после измерения. Интерактор делает `endl` после каждого ответа; запись такого журнала через WSL `/mnt/c` сильно замедляет обмен. Первый дополнительный WSL-прогон с журналами на `/mnt/c` был остановлен ограничением измерителя в 60 с wall time. Полный WSL-прогон с нативной временной папкой завершился и приведён в таблице.

У Cangjie в прежнем полном Windows-прогоне теста 15 было 6.125 с CPU и 27.68 МиБ рабочего набора. Память C++ заметно меньше; фиксированного коэффициента ускорения по отдельным запускам не заявляем. Нагрузка компьютера не фиксировалась, а расположение журналов менялось.

Для сервера предназначен **GCC C++ 14.2 (64-bit, C++20, msys2)**. Локальная Windows-проверка использовала GCC той же версии из w64devkit 2.0.0, а не серверный дистрибутив MSYS2. Скрытые тесты и серверный вердикт не проверены; превышения CPU в отдельных локальных прогонах означают, что TL на сервере пока исключить нельзя.

## Повторение

Windows, установленный GCC/MinGW:

```powershell
.\build_cpp.ps1 -Test
python tools/check_open_tests.py --language cpp
```

Linux/WSL:

```bash
bash ./build_cpp.sh --test
python3 tools/check_open_tests.py --language cpp
```

Параметры измерителя: `--solution`, `--compiler`, `--report`; `--test 15` запускает один тест. `--reference-traces` позволяет сверить числовые ответы с каталогом предыдущего полного прогона. Для сохранённой Cangjie-версии предусмотрен `--language cangjie --sdk <путь>`.
