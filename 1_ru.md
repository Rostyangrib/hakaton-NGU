# Строительство газопровода

Перевод документа `1.pdf` на русский язык. Цветные схемы из примеров представлены текстовыми схемами.

Крупная компания строит подземный газопровод в Китайскую Народную Республику. На первом этапе работ выкапывают траншею и укладывают в неё трубы; сварка швов на этом этапе не выполняется. В распоряжении строителей есть пакет труб различной длины: от 1 до 40 метров, причём длина каждой трубы выражается целым числом. Также имеется многофункциональный трубоукладчик с числовым программным управлением, который по команде управляющей программы может выкопать 20 метров траншеи или удлинить существующую траншею на эту величину.

В трубоукладчик загружают пакет труб. Машина извлекает из пакета одну трубу, измеряет её длину и укладывает в траншею на расстоянии от её начала, которое определяет управляющая программа. При этом каждой трубе присваивается PID - уникальный номер в порядке извлечения из пакета, начиная с 1. Трубоукладчик также может извлечь трубу из траншеи по её PID. Из-за чрезвычайно высокого риска повреждения перемещать уже уложенные трубы внутри траншеи запрещено.

Поскольку проект очень важен для компании, периодически приезжает группа контроля качества и проверяет уложенные трубы. На время проверки укладка приостанавливается. Группа может указать PID одной или нескольких труб, повреждённых при укладке: их необходимо извлечь и отправить на переработку. После этого укладка возобновляется.

Как только пакет труб опустеет, немедленно приезжает группа оценки эффективности. Она рассчитывает KPI, равный отношению суммарной длины труб, уложенных в траншее, к длине выкопанной траншеи. Ваша задача - написать управляющую программу для трубоукладчика.

## Протокол взаимодействия

Это интерактивная задача. Вместо файлового ввода и вывода вы будете работать со специальной программой, которая называется **интерактором**. Взаимодействие с ней осуществляется через стандартные потоки ввода и вывода.

Интерактор по одной передаёт команды из сценария. Команды представляют собой целые числа:

- `L` - уложить трубу заданной длины, где `L ∈ [1, 40]`.
- `-K` - извлечь из траншеи трубу с `PID = K`.
- `0` - специальная команда, обозначающая конец последовательности.

В ответ на каждую команду ваше решение должно выдать одну или несколько инструкций, определяющих дальнейшие действия.

Возможные выходные инструкции:

1. Если получена команда уложить очередную трубу, ответ должен состоять из двух целых чисел `N D`, где:
   - `N ≥ 0` означает, что нужно выкопать или удлинить траншею на `N × 20` метров;
   - `D ≥ 0` означает, что трубу нужно уложить на расстоянии `D` от начала траншеи.
2. Если получена команда извлечь трубу, решение должно вывести расстояние от начала траншеи до начала извлекаемой трубы.
3. Если получена команда `0`, ответ не требуется. Программа должна немедленно завершить работу.

Гарантируется, что общее количество входных команд в любом тестовом сценарии не превышает **200 000**.

После каждой выведенной инструкции обязательно выводите символ конца строки и сбрасывайте буфер выходного потока с помощью функции `flush` используемого языка программирования. Иначе решение может получить вердикт **Timeout** - превышение времени ожидания.

## Пример

В исходном документе для удобства чтения команды в примере разделены пустыми строками. **Ваша программа не должна выводить пустые строки.**

Ниже приведены два разных примера взаимодействия с одной и той же последовательностью входных команд.

В текстовых схемах один символ соответствует одному метру траншеи. Символ `.` обозначает свободное место, а `A`, `B`, `C` и `D` - трубы с PID 1, 2, 3 и 4 соответственно. Разделитель `/` отмечает границу между 20-метровыми участками и сам длины не имеет. В строке показано состояние после выполнения команды.

### Первый вариант

| Стандартный поток ввода | Стандартный поток вывода | Схема                  |
| ----------------------- | ------------------------ | ---------------------- |
| `1`                     | `1 0`                    | `A...................` |
| `4`                     | `0 1`                    | `ABBBB...............` |
| `15`                    | `0 5`                    | `ABBBBCCCCCCCCCCCCCCC` |
| `-2`                    | `1`                      | `A....CCCCCCCCCCCCCCC` |
| `3`                     | `0 1`                    | `ADDD.CCCCCCCCCCCCCCC` |
| `-1`                    | `0`                      | `.DDD.CCCCCCCCCCCCCCC` |
| `0`                     | Ответ не требуется       | `.DDD.CCCCCCCCCCCCCCC` |

### Альтернативная последовательность выходных инструкций

| Стандартный поток ввода | Стандартный поток вывода | Схема |
| --- | --- | --- |
| `1` | `1 0` | `A...................` |
| `4` | `0 1` | `ABBBB...............` |
| `15` | `0 5` | `ABBBBCCCCCCCCCCCCCCC` |
| `-2` | `1` | `A....CCCCCCCCCCCCCCC` |
| `3` | `1 20` | `A....CCCCCCCCCCCCCCC/DDD.................` |
| `-1` | `0` | `.....CCCCCCCCCCCCCCC/DDD.................` |
| `0` | Ответ не требуется | `.....CCCCCCCCCCCCCCC/DDD.................` |

### Пояснение к примеру

Входная последовательность в обоих примерах означает следующее: извлечь из пакета трубу длиной 1 метр и уложить её; последовательно сделать то же самое с трубами длиной 4 и 15 метров; извлечь из траншеи трубу с `PID = 2`, то есть вторую трубу, вынутую из пакета; извлечь из пакета и уложить трубу длиной 3 метра; извлечь из траншеи трубу с `PID = 1`.

Решение считается некорректным, если какую-либо инструкцию укладки невозможно выполнить из-за нехватки свободного места начиная с указанного расстояния от начала траншеи. Обе приведённые выше последовательности выходных инструкций корректны.

Однако у этих решений разные KPI: **0,9** для первой последовательности и **0,45** для второй. Следовательно, на этой входной последовательности первая стратегия лучше.

При получении некорректной команды интерактор немедленно завершает работу и возвращает сообщение с описанием ошибки. KPI некорректного решения всегда равен **0**.

Длина выкопанной траншеи также ограничена: она не должна превышать **100 000 000 метров**. При превышении этого значения решение становится некорректным.

Во время соревнования участники также могут отправлять решения в NSUts и получать результаты по всем открытым тестам. Решения можно отправлять многократно без штрафов. Однако для расчёта итогового балла будет использована **только последняя попытка**.

Итоговый балл решения равен сумме произведений KPI на соответствующий вес по всем тестам, как открытым, так и закрытым:

$$
\mathrm{Score} = \sum_{i=1}^{30} \mathrm{KPI}_i \cdot \mathrm{weight}_i
$$

Побеждает решение с максимальным итоговым баллом. Если несколько решений набрали одинаковый балл, победитель определяется по минимальному суммарному процессорному времени выполнения на этих тестах.

Обратите внимание: в большинстве тестов максимально возможный KPI близок к **1**.

## Ограничения

Решение должно обработать всю последовательность менее чем за **5 секунд процессорного времени** и использовать менее **256 МБ оперативной памяти**.

## NSUts

Список всех своих отправок можно найти на странице **«Результаты»** в системе проверки NSUts.

Для каждой проверенной отправки на этой странице доступны две ссылки: **«Открыть отчёт о тестировании»** и **«Скачать результаты тестирования»**.

По первой ссылке можно открыть подробный отчёт о проверке: статус, KPI, затраченное процессорное время и балл для каждого теста.

По второй ссылке можно скачать ZIP-архив, содержащий вывод вашей программы для каждого теста, а также сообщение об ошибке интерактора, если программа нарушила протокол взаимодействия или выдала некорректную команду.

## Материалы

Архив со всеми необходимыми материалами - открытыми тестами и интерактором - можно скачать из NSUts. Он содержит следующие файлы:

| Имя файла | Описание |
| --- | --- |
| `tests/*.in` | Открытые тесты: последовательности входных команд, которые будут передаваться вашему решению. Их можно анализировать, чтобы понять, какие входные данные могут встретиться. |
| `interactor.cpp`, `testlib.h` | Исходный код интерактора - специальной программы для проверки вашего решения на предоставленном наборе открытых тестов. |
| `interactor.exe` | Готовый исполняемый файл интерактора для локальной проверки решения в Windows. |
| `interactor` | Готовый исполняемый файл интерактора для локальной проверки решения в Linux. |
| `runner.py` | Скрипт Python, который следует использовать для локального запуска тестов вашего решения. |

### Запуск локальных тестов

1. Убедитесь, что на локальном компьютере установлен **Python 3.5 или новее**.
2. Чтобы запустить решение на всех тестах из каталога `tests`, выполните команду:

   ```text
   python runner.py -d tests <your_solution_binary>
   ```

   Здесь `<your_solution_binary>` - исполняемый файл вашего решения. Если команда запуска состоит из нескольких слов, заключите её в кавычки. Например, для решения на Java:

   ```text
   python runner.py -d tests "java -jar solution.jar"
   ```

3. Чтобы вместо всех тестов запустить решение только на тесте `tests/1.in`, выполните:

   ```text
   python runner.py -i tests/1.in <your_solution_binary>
   ```
