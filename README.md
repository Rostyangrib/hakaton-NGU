# Строительство газопровода — хакатон НГУ

Интерактивное решение задачи размещения труб с удалениями. Язык реализации: **Cangjie 1.0.5 LTS**.

## Материалы

- `1.pdf` — исходное условие на английском языке.
- `1_ru.md` — перевод условия на русский язык.
- `2.zip` — исходный архив организаторов.
- `case2_materials/` — распакованные интерактор, скрипт запуска и 15 открытых тестов.
- `case2_dataset_analysis.ipynb` — выполненный анализ распределений длин, удалений и активной нагрузки.
- `CHAGELOG.md` — история завершённых этапов с идентификаторами коммитов. Название сохранено по запросу участника.

Исходные материалы организаторов не изменяются. SDK, исполняемые файлы решения и временные результаты не включаются в Git.

## Алгоритм

Первые 200 поступлений используют Best Fit. На следующих 200 поступлениях постепенно включается оценка свободных промежутков по статистике последних 1024 поступлений. Удаление трубы не уменьшает число поступлений и не удаляет её длину из статистики.

Для `k` предыдущих поступлений в окне частота длины `l` сглаживается равномерным априорным распределением общей массой 1:

```text
p[l] = (count[l] + 1/40) / (k + 1)
q[l] = 0.75 * p[l] + 0.25 * l * p[l] / sum(j * p[j])
Phi(g) = g * sum(q[l] для l > g), 1 <= g < 40
Phi(0) = Phi(g >= 40) = 0
a = clamp((номер текущего поступления - 200) / 200, 0, 1)
score(h, x) = (1-a) * (h-x) + a * (Phi(h-x) - Phi(h))
```

Здесь `h` — длина свободного промежутка, `x` — длина текущей трубы. Выбирается минимальный `score`. При равенстве с точностью `1e-9` выбирается меньший промежуток, затем меньшая начальная позиция. Укладка выполняется с левого края. Текущая труба попадает в статистику после выбора места.

Свободные интервалы хранятся в согласованных индексах по позиции и длине. Позиционный индекс использует хеш-таблицы начала и конца интервала: для объединения нужны только точно соседние границы. Индекс длин использует минимальные кучи начальных позиций с ленивым удалением; устаревшая позиция отбрасывается при достижении вершины. Это сохраняет выбор самого левого действующего промежутка. После удаления соседние свободные интервалы объединяются. Если подходящего промежутка нет, используется свободный хвост и докапывается минимально необходимое количество участков по 20 м. Траншея не сокращается.

За один поиск оценивается не более 41 кандидата: по одному для каждой подходящей длины до `x+39` и один минимальный промежуток длиной от `x+40`. Для длин меньше 80 есть прямой массив корзин, для больших — упорядоченный индекс. Направленные обходы `TreeMap` и сортировка всех промежутков в рабочем цикле не используются: в Cangjie 1.0.5 они оказались слишком дорогими на предоставленных тестах. Сортировка снимка состояния нужна только модульным проверкам. Число отложенных записей в кучах ограничено числом операций добавления свободных интервалов.

Параметры являются начальными гипотезами. Превосходство над Best Fit без отдельного сравнения не заявляется.

## Сборка и запуск в Windows

Нужны Windows x64 и [Cangjie SDK 1.0.5 LTS](https://cangjie-lang.cn/download/1.0.5). Скачайте ZIP из официального центра и распакуйте его так, чтобы компилятор находился в `.tools/cangjie-1.0.5/cangjie/bin/cjc.exe`, либо передайте свой путь через `-SdkPath`.

SHA-256 официального ZIP:

```text
08c6c1dd0de73396f63ac85085d635e79ce84fef98d330cb00869b4fc8f1cb2e
```

```powershell
# Сборка с оптимизацией -O2
.\build.ps1

# Сборка и модульные проверки
.\build.ps1 -Test

# SDK в другом каталоге
.\build.ps1 -SdkPath 'C:\path\to\cangjie' -Test
```

Скрипт меняет переменные окружения только текущего процесса. Бинарные файлы сохраняются в `build/`, журнал модульных проверок — в `build/unit-tests.log`.

Для запуска из отдельного PowerShell сначала загрузите окружение SDK:

```powershell
. .\.tools\cangjie-1.0.5\cangjie\envsetup.ps1
.\build\solution.exe
```

Программа получает только команды интерактора, без веса и количества команд из заголовка тестового файла. ASCII-ввод и вывод используют штатное взаимодействие Cangjie с системными функциями: `ReadFile`/`WriteFile` в Windows, `read`/`write` в Unix. Дополнительный C/C++ исходник или отдельная сторонняя библиотека не нужны. Windows API работает непосредственно с байтами. При неуспешном `ReadFile` редкий резервный `_read` различает конец потока и ошибку чтения; код не зависит от сохранения Win32-кода ошибки между переходами через C FFI.

Каждый ответ немедленно записывается целиком функцией `flushReply`. У дескрипторной записи нет буфера stdio, поэтому отдельный `fflush` не нужен; ответы не объединяются в пачки. Чтение запрашивает доступные байты, не дожидаясь заполнения 4096-байтового буфера. На `0` программа завершается без ответа. Небольшие native-буферы и счётчики прочитанных/записанных байтов освобождаются в `finally`, диагностика выводится только в `stderr`.

На Linux исходник собирается установленным SDK командой `cjc solution.cj -O2 -o solution`. Локальная проверка в Linux пока не выполнялась.

## Состояние

Алгоритм реализован и собран Cangjie 1.0.5 с `-O2` без предупреждений. Пройдены 13 модульных проверок, включая независимую метровую модель, 100 коротких и 6 длинных случайных сценариев, а также многократное переиспользование одного промежутка. Потоковый протокол проверен на CRLF, пробелах, частичных командах и немедленном завершении на `0`.

Все 15 открытых тестов приняты официальным интерактором: сумма баллов 28,3486066854 при сумме весов 32,1. KPI теста 15 — 0,947714. В последнем полном Windows-прогоне CPU теста 15 составил 6,125 с, в отдельном запуске той же сборки — 4,297 с; память около 27,7 МиБ. Лимит CPU 5 с пока нельзя считать устойчиво выполненным. Выполняется дополнительная проверка Linux; подробный воспроизводимый отчёт будет сохранён отдельно.

Локальная целевая версия — 1.0.5 LTS. Версия компилятора в NSUts пока неизвестна; серверная совместимость требует отдельной проверки.
