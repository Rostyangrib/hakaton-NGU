## Алгоритм

Первые 200 поступлений используют Best Fit. На следующих 200 поступлениях постепенно включается оценка свободных промежутков по статистике последних 1024 поступлений. Удаление трубы не уменьшает число поступлений и не удаляет её длину из статистики.

Для `k` предыдущих поступлений в окне частота длины `l` сглаживается равномерным априорным распределением общей массой 1:

```text
p[l] = (count[l] + 1/40) / (k + 1)
q[l] = 0.75 * p[l] + 0.25 * l * p[l] / sum(j * p[j])
Phi(g) = g * sum(q[l] для l > g), 1 <= g < 40
Phi(0) = Phi(g >= 40) = 0
a = clamp((номер текущего поступления - 200) / 200, 0, 1)
score(h, x) = (1-a) * (h-x) + a * (Phi(h-x) - Phi(h))
```

Здесь `h` — длина свободного промежутка, `x` — длина текущей трубы. Выбирается минимальный `score`. При равенстве с точностью `1e-9` выбирается меньший промежуток, затем меньшая начальная позиция. Укладка выполняется с левого края. Текущая труба попадает в статистику после выбора места.

В C++ свободные интервалы хранятся в двух согласованных индексах: `std::map` по началу и `std::map<длина, std::set<начало>>` по длине. После удаления соседние интервалы объединяются. Если подходящего промежутка нет, используется свободный хвост и докапывается минимально необходимое количество участков по 20 м. Траншея не сокращается.

За один поиск оценивается не более 41 кандидата: по одному для каждой подходящей длины до `x+39` и один минимальный промежуток длиной от `x+40`. Сложность команды — `O(log G + 40)`, где `G` — число свободных интервалов. Формулы, параметры и порядок выбора кандидатов сохранены при переносе с Cangjie.

Параметры являются начальными гипотезами. Превосходство над Best Fit без отдельного сравнения не заявляется.

## Сборка C++

Для Linux/WSL:

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic solution.cpp -o solution
bash ./build_cpp.sh --test
```

Для Windows с GCC/MinGW:

```powershell
.\build_cpp.ps1 -Test
# Компилятор в другом каталоге:
.\build_cpp.ps1 -CompilerPath 'C:\msys64\ucrt64\bin\g++.exe' -Test
```

Скрипт Windows использует `g++.exe` из `.tools/w64devkit/bin/` либо из PATH. Локально доступен переносимый [GCC 14.2 из w64devkit 2.0.0](https://github.com/skeeto/w64devkit/releases/tag/v2.0.0). Компилятор и бинарные файлы исключены из Git. Windows-сборка статическая; дополнительный Cangjie SDK для C++ не нужен. Исходник также использует только возможности C++17.

Результат: `build/solution-cpp.exe` в Windows, `build/solution-cpp` в Linux. Журналы модульных тестов сохраняются в `build/unit-tests-cpp-windows.log` и `build/unit-tests-cpp-linux.log`.

Программа получает команды интерактора без заголовка тестового файла. Ввод читает доступные байты и не дожидается заполнения буфера. Каждый ответ полностью отправляется сразу, до чтения следующей команды; `0` завершает программу без ответа. Вывод идёт напрямую через системные функции, без накопления ответов в stdio. Диагностика выводится только в `stderr`.
