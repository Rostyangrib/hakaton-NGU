## 2026-10-16 — Адаптивное решение и модульные проверки

Коммит: `9edb37a` — «Реализован адаптивный алгоритм укладки труб на Cangjie».

- Реализованы Best Fit на прогреве, окно 1024 поступлений, сглаживание, дополнительный вес длинных труб и плавное включение статистики с 201-го по 400-е поступление.
- Добавлены два индекса свободных промежутков, объединение соседних участков, использование хвоста перед расширением и ограничение поиска 41 кандидатом.
- Реализован интерактивный протокол с немедленным `flush` и завершением на `0`.
- Подготовлен `build.ps1`; SDK 1.0.5 установлен локально после проверки официального SHA-256. Исполняемые файлы и SDK исключены из Git.
- Учтено исключение Cangjie 1.0.5 при направленном обходе пустого `TreeMap`; стандартные потоки переведены на актуальный `std.env`.
- Проверки: сборка `-O2` без предупреждений; 12 модульных тестов прошли, включая 27 200 случайных команд с независимой метровой моделью и сверкой ускоренного поиска с полным перебором. Первый официальный тест через `runner.py`: балл 0,09, KPI 0,9.

## 2026-10-16 — Выполнение ограничения CPU

Коммит: `0b2d5fe` — «Ускорены индексы промежутков и интерактивный ввод-вывод».

- Первый полный прогон выявил превышения CPU; это не было принято за успешное выполнение ограничений.
- Направленные обходы позиции заменены точными хеш-индексами границ. Короткие длины доступны через массив корзин, начальные позиции — через минимальные кучи с ленивым удалением.
- Ввод и вывод переведены на непосредственное чтение/запись дескрипторов через штатный C FFI Cangjie. Ответ записывается целиком сразу; буферы освобождаются при завершении. Для Windows включён бинарный режим стандартных дескрипторов текущего процесса.
- Формулы статистики, параметры, порядок выбора кандидатов и правила разрешения равенств сохранены.
- Проверки: 13 модульных тестов без ошибок, включая повторное использование одного промежутка; потоковые ответы, CRLF, пробелы, разбиение команды на части и отсутствие ответа на `0`. Отдельный прогон теста 15: KPI 0,947714, CPU 3,969 с, пиковый рабочий набор около 27,6 МиБ. Финальный полный прогон всех сценариев выполняется следующим этапом.

## 2026-10-16 — Версия для пробной отправки на сервер

Коммит: `79de461` — «Сокращены накладные расходы ввода-вывода в Windows».

- Windows-ввод и вывод используют `ReadFile`/`WriteFile`; редкий резервный `_read` различает закрытый поток и ошибку чтения. Native-буферы и счётчики освобождаются при завершении.
- Проверки: сборка Cangjie 1.0.5 без предупреждений; 13 модульных тестов; потоковый протокол и 10 000 команд через границы входного буфера; все 15 открытых тестов приняты официальным интерактором.
- Сумма баллов — 28,3486066854; KPI теста 15 — 0,947714. В полном Windows-прогоне CPU теста 15 — 6,125 с, в отдельном запуске той же сборки — 4,297 с, память около 27,7 МиБ. Устойчивое выполнение лимита CPU 5 с пока не подтверждено.
- Версия передана пользователю для проверки на сервере; исходник `solution.cj` закреплён данным коммитом. Формулы и решения по укладке сохранены.

## 2026-10-17 — Перенос на C++20

Коммит: `85b9a62` — «Перенесён адаптивный алгоритм на C++20».

- По запросу пользователя основным решением стал самостоятельный `solution.cpp`, совместимый с GCC C++20/C++17. Cangjie-версия сохранена для сравнения.
- Параметры, сглаживание, окно, прогрев, формулы и порядок выбора сохранены. Свободные интервалы индексируются `std::map` и `std::set`, без необходимых для Cangjie обходных оптимизаций коллекций.
- Добавлены Windows/Linux-сборка, 13 C++ модульных проверок и независимая метровая модель; проверены 27 200 случайных команд и повторное использование промежутков.
- Каждый ответ немедленно записывается через Windows API либо POSIX `write`; ASCII-форматирование выполняется без stdio-буфера, проверены EOF, CRLF, разбиение команд, `0` и границы буфера.
- Сборка GCC 14.2 в Windows без предупреждений. Все 15 тестов приняты интерактором; каждый числовой ответ совпал с Cangjie; сумма баллов 28,3486066854. В полном прогоне теста 15 — 5,172 с CPU и около 5,4 МиБ памяти. Устойчивое выполнение CPU-лимита в Windows пока не подтверждено; измерения и отчёт продолжаются.

## 2026-10-17 — Финальные прогоны и отчёт

Коммит: `653d616` — «Добавлены воспроизводимые прогоны C++ и отчёт по тестам».

- Добавлен `tools/check_open_tests.py`: официальный интерактор, независимая сверка балла, полный CPU процесса решения, память, проверки потокового протокола и SHA-256 исходника, бинарного файла, интерактора и входов.
- Журналы интерактора пишутся в нативную системную временную папку и копируются в проект после измерения. Синхронная запись через WSL `/mnt/c` приводила к превышению 60-секундного wall-таймаута измерителя; интерактор и решение при исправлении методики не менялись.
- Все 15 открытых тестов корректны в Windows и Linux/WSL. Все числовые ответы на 280 156 командах совпали с Cangjie-версией. Сумма баллов — 28,3486066854; штатный `runner.py` подтвердил 28,348606686 с учётом округления.
- Финальный Windows-прогон GCC 14.2: максимум 3,141 с полного CPU и 5,44 МиБ рабочего набора; все тесты в этом прогоне уложились в ограничения. В дополнительном WSL-прогоне тест 15 дал 6,448 с CPU и превысил 5 с. Предыдущий Windows-замер 5,172 с и отдельный запуск 3,219 с сохранены в JSON; серверный TL пока исключить нельзя.
- Пройдены 13 модульных тестов Windows/Linux и те же проверки под AddressSanitizer + UBSan. Исходник `solution.cpp` остался на версии `85b9a62`; все 20 исходных файлов архива сохранены побайтово.
- Сохранены `TEST_REPORT.md`, полная таблица тестов, JSON, журналы модульных проверок и вывод штатного скрипта; обновлена инструкция сборки и повторного прогона.
