Основное решение для отправки — **`solution.cpp`**. Компилятор: **GCC C++ 14.2 (64-bit, C++20, msys2)**. Это самостоятельный файл с интерактивным вводом и немедленной отправкой каждого ответа.

После разбора тестов 3, 4, 5, 9, 10 Best Fit дополнен оценкой соседей после массовых удалений и группировкой повторяющихся однородных серий. Новый официальный прогон: **29,471336218281** балла против **28,375837599373** у чистого Best Fit. Все 15 публичных тестов корректны; улучшены 3, 5, 9, 10, KPI остальных сохранён. В тесте 4 исходный KPI уже оптимален.

Разбор причин, таблица всех KPI, границы качества, параметры и известный контрпример: [BEST_FIT_IMPROVEMENT.md](BEST_FIT_IMPROVEMENT.md). Машиночитаемые результаты: [официальный прогон](reports/kpi_improved_windows.json), [сравнение KPI](reports/kpi_improvement.csv), [отдельный вклад эвристик и синтетические сценарии](reports/packing_benchmark.csv).

## Сборка и проверка

```powershell
.\build_cpp.ps1 -Test
python tools/check_open_tests.py --source solution.cpp --report reports/kpi_improved_windows.json
```

Скрипт находит локальный `.tools/w64devkit/bin/g++.exe` либо компилятор из PATH. Можно передать `-CompilerPath 'C:\msys64\ucrt64\bin\g++.exe'`. Результат — `build/solution-cpp.exe`; лог модульных тестов — `build/unit-tests-cpp-windows.log`. SDK и бинарные файлы в Git не включаются.

Linux/WSL:

```bash
bash ./build_cpp.sh --test
python3 tools/check_open_tests.py --source solution.cpp --report reports/kpi_improved_linux.json
```

Окончательный официальный прогон этой версии выполнен в Windows. Команды Linux приведены для воспроизведения; результаты предыдущей C++-версии нельзя переносить на новую.

Сравнение четырёх режимов без накладных расходов интерактора, из корня проекта при наличии g++ в PATH:

```powershell
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -static tools/benchmark_packing.cpp -o build/benchmark-packing.exe
.\build\benchmark-packing.exe | Set-Content -Encoding utf8 reports/packing_benchmark.csv
python tools/report_improvement.py
```

Бенчмарк передаёт алгоритму команды по одной. Скрипт отчёта сверяет все 30 строк Best Fit/нового решения с двумя официальными JSON, проверяет SHA исходника и совпадение хешей входных тестов.

## Алгоритм

- Обычно выбирается самый короткий подходящий свободный участок. При удалении соседние свободные участки объединяются; при необходимости расширения сначала используется хвост траншеи.
- После массового удаления временно учитывается доля ранее удалённых труб той же длины у соседей участка. Это помогает сохранить дырку, которая может объединиться с соседней удаляемой трубой.
- После наблюдения удаления каждой второй трубы в однородной серии следующая похожая серия размещается с двух краёв участков. Ограниченное резервирование помогает получить крупные свободные блоки после следующего удаления. Размер новой серии оценивается по прошлой; первая её труба не вызывает прогнозного расширения.

Решение использует только прошедшие команды. Номера тестов, готовые последовательности и фиксированные размеры публичных серий в нём отсутствуют. Два свободных индекса и индекс активных труб занимают O(P+G) памяти. На шаге оценивается не более 11 кандидатов. Преимущество на скрытых данных не гарантируется: прогноз серии может ошибиться, известный контрпример приведён в отчёте.
